# Code conventions

Rules for naming and structuring code in this repository. They apply to every workspace except
`apps/web/src/components/base/`, which is generated by the shadcn CLI and kept as generated.

For the architecture (layers, providers, component categories), see [README.md](README.md).

---

## Naming

### Booleans start with `is`, `has` or `should`

Variables, parameters, props, object fields and DB columns alike.

```ts
// ✅
(isPublic, isCancelled, isSaving, isNullable, isChanged, hasChanges, hasBody, shouldRetry);

// ❌
(public, cancelled, saving, nullable, changed, changes, body, retry);
```

The DB column follows the same rule in `snake_case`: `is_cancelled`.

**Exception:** names imposed by an external API keep that API's name, e.g. cookie options
(`httpOnly`, `secure`, `sameSite`) or HTML attributes (`disabled`, `required`).

### Functions start with an action verb

The name says what the function does: `get`, `select`, `search`, `update`, `create`, `map`, `compute`,
`generate`, `define`, `register`, `send`, `parse`, `format`, `render`, `verify`…

```ts
// ✅
(searchTaskOccurrences,
  selectTaskTemplatesByIds,
  mapToTaskTemplate,
  computeNbOfOccurrencesBefore,
  defineRoutes,
  sendRequest,
  createDeferred,
  getCallSignal);

// ❌
(taskOccurrences, templatesByIds, taskTemplate, nbOfOccurrences, routes, request, deferred, signalOfCall);
```

- **Converters** are `map<A>To<B>` (`mapToTaskTemplate`, `mapTaskPriorityToNumber`), not `<a>To<b>`.
- **Event props and callbacks** are named after the event: `on<Event>` (`onChange`, `onSave`,
  `onRowChange`). This is the one exception to the verb rule, because the name describes when the
  callback runs, not what it does.
- **React components** are `PascalCase` nouns (`TaskTemplateTable`), **hooks** start with `use`.

### Variables and constants

- `camelCase` for variables, parameters and module-level values built from code (`columnDefinitions`,
  `globalStore`, `taskTemplateSchema`).
- `UPPER_SNAKE_CASE` for module-level constant values: configuration, limits, fixed lists
  (`AUTH_COOKIE_NAME`, `MAX_LOGIN_ATTEMPTS`, `MAX_OCCURRENCES_PER_TASK`, `INTERVAL_UNITS`).
- **Quantities carry their unit** as a suffix: `Ms`, `S`, `Mn` (`SHUTDOWN_TIMEOUT_MS`,
  `CACHE_PREFIX_TO_TTL_S`, `estimatedMn`, `ttlMs`).
- **Full words**, no abbreviations: `taskTemplate`, not `tt`; `completedOccurrence`, not `co`. Single
  letters are only for `e` (events, errors in `catch`) and `i` (indexes).

### Types

| Kind                                           | Rule                                                     | Example                               |
| ---------------------------------------------- | -------------------------------------------------------- | ------------------------------------- |
| Types and interfaces                           | `PascalCase`                                             | `TaskTemplate`, `HttpRoute`           |
| Generic parameters                             | `T` + a name                                             | `TRow`, `TData`, `TFeatures`          |
| Domain types (`operations/types.operation.ts`) | plain name                                               | `User`, `TaskTemplate`                |
| DTO types                                      | `DTO` suffix when the name clashes with a domain type    | `TaskTemplateDTO`, `UserDTO`          |
| Zod schemas                                    | `camelCase` + `Schema`, type inferred next to it         | `loginRequestSchema` → `LoginRequest` |
| Route schemas                                  | `<operation>RequestSchema` / `<operation>ResponseSchema` | `updateTaskTemplatesRequestSchema`    |
| Drizzle tables                                 | `db` prefix                                              | `dbUsers`, `dbTaskTemplates`          |

### Names follow the operation

One name per operation, across all layers:

| Layer                       | Name                                                             |
| --------------------------- | ---------------------------------------------------------------- |
| Operation file and function | `updateTaskTemplates.operation.ts`, `updateTaskTemplates()`      |
| DTO schemas and types       | `updateTaskTemplatesRequestSchema`, `UpdateTaskTemplatesRequest` |
| Store query or mutation     | `updateTaskTemplates`                                            |

Use the same word for the same concept everywhere: a concept that is a "template" in the database is
a "template" in the DTO, the store and the components. Don't introduce a synonym.

## Functions

### Prefer `function` declarations

Use `function` for every named, standalone function: module-level helpers, exported functions, React
components, and functions defined inside a factory.

```ts
// ✅
export function defineQueries(db: Database) {
  async function selectTaskTemplatesByIds(userId: string, ids: string[]) { ... }
}

// ❌
const selectTaskTemplatesByIds = async (userId: string, ids: string[]) => { ... };
```

Arrow functions are for inline use: callbacks (`items.map((item) => ...)`, `onClick={() => ...}`),
object members in a builder (`addGetters({ todos: (state) => state.todos })`), and short closures that
capture local variables inside a function.

## File structure

### Main function first, helpers below

A file reads top-down: what it does first, how it does it after.

1. Imports
2. Types and constants needed to understand the main function
3. **The main exported function or component**
4. Helper functions, in the order the main function uses them

`function` declarations are hoisted, so helpers can live below the code that calls them.

```ts
export async function searchTaskOccurrences(...) {
  ...generateTaskOccurrences(...)
}

function generateTaskOccurrences(...) { ... }

function generateTaskOccurrence(...) { ... }
```

### One main export per file, named like the file

`TaskTemplateTable.tsx` exports `TaskTemplateTable`; `updateTaskTemplates.operation.ts` exports
`updateTaskTemplates`. Named exports only, no `export default`.

### File naming

| Kind                       | Pattern                                     | Example                                                     |
| -------------------------- | ------------------------------------------- | ----------------------------------------------------------- |
| Operation                  | `<operationName>.operation.ts`              | `searchTaskTemplates.operation.ts`                          |
| Operation types and errors | `types.operation.ts`, `errors.operation.ts` |                                                             |
| Backend provider           | `<name>.provider.ts`                        | `cache.provider.ts`                                         |
| Provider internals         | `<role>.<provider>.ts`                      | `queries.database.ts`, `routes.http.ts`, `adapters.http.ts` |
| Provider errors            | `errors.<provider>.ts`                      | `errors.auth.ts`                                            |
| DTO                        | `<feature>.dto.ts`                          | `task.dto.ts`                                               |
| Frontend lib               | `<name>.lib.ts`                             | `api.lib.ts`, `string.lib.ts`                               |
| React components           | `PascalCase.tsx`, named like the component  | `TaskTemplateTable.tsx`                                     |
| Containers / pages         | `…Container.tsx` / `…Page.tsx`              | `TaskTemplatesEditContainer.tsx`                            |
| shadcn base components     | `kebab-case.tsx` (generated)                | `button.tsx`                                                |
| Tests                      | next to the code, `<name>.test.ts(x)`       | `queries.test.tsx`                                          |

## TypeScript

- `import type` for type-only imports (enforced by ESLint and `verbatimModuleSyntax`).
- Strict mode, including `noUncheckedIndexedAccess`.
- No TypeScript-only runtime syntax (`enum`, `namespace`, parameter properties): the backend runs on Node
  type stripping (`erasableSyntaxOnly`). Use `as const` objects or arrays instead of enums.
- Backend and shared packages import with the `.ts` extension.
- Avoid `any` and `as`. When a cast is unavoidable (e.g. a correlated union TypeScript can't follow),
  keep it inside the generic or library code, not in every caller.
